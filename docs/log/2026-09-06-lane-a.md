## What I did

1. **Found and fixed a real bug: the in-memory storage fallback didn't persist across
   requests.** `api/_lib/storage.mjs`'s `createStorage()` called `createMemoryStorage()`
   fresh on every invocation — every API handler calls `createStorage()` per request, and
   each call got brand-new, empty `Map`s. Without `GITHUB_TOKEN`/`GITHUB_REPO` set (today's
   actual production state, since gate item #3 in `PROGRESS.md` hasn't been done yet), this
   meant the entire identity + lots + bids flow was silently broken end to end: request-code
   writes a one-time code to one in-memory store, verify-code creates a *second, empty* store
   and always returns `no_code`. I reproduced this with a two-line repro before touching
   anything, then fixed it with a module-level singleton for the fallback path only (left
   `createMemoryStorage()` itself untouched — it's still a fresh-instance factory, which is
   what all 28 existing unit tests rely on). All 28 tests still pass. This is very likely
   *the* reason nobody could ever run the identity round trip locally before now — it's not
   about the GitHub adapter or missing env vars at all, it was one line in the fallback.

2. **M1.1 — wired `assets/js/store.js` to the live API**, additively, without touching the
   140-lot fictional catalogue (still `localStorage`-only, per the mission's rule against
   ever presenting invented lots as real). Added:
   - A real identity (`localStorage` key `phj-identity-v1`, separate from the fictional
     `phj-store-v1` bid data) using the same email + one-time-code flow as `sell.html`.
   - A `#/live` route: lists real, reviewer-approved lots fetched from `GET /api/lots`.
   - A `#/live/:id` route: real lot detail, real bid history from `GET /api/lots/:id/bids`,
     and a real bid form that POSTs to `/api/lots/:id/bids` with the signed session token —
     the server (`auction.mjs`) is the only authority on whether a bid stands, exactly as
     M1's mission requires. Server rejection reasons (`too_low`, `already_winning`,
     `closed`, `unauthenticated`) are shown back to the bidder in plain language.
   - Fails soft: if the API is unreachable, Live Lots shows an offline notice and the rest
     of the prototype store keeps working from `localStorage` alone, per `CLAUDE.md`'s
     "static site, API optional" promise.
   - Reused `plateSVG()` for real lots too (now that `category` round-trips, see below), so
     a real lot gets the same generated two-ink plate as a fictional one — never a faked
     photo, per the mission's rule.

3. **M1.4 — `api/lots.mjs` was silently dropping `category`.** Added it to `createLot()`'s
   payload and to `validateSubmission()` (checked against the same 7 categories `sell.html`'s
   `<select>` offers), so a real lot actually carries the field its plate art depends on.

4. **M1.3 — linked `sell.html` from the store**, both directions: `store.html`'s `.topnav`
   now has "Live lots" and "List a lot" links; `sell.html`'s nav got "Live lots" too so a
   seller can see what's already up.

## Where this leaves M1

A stranger can now, in a real browser: submit a lot (`sell.html`, already worked before
today), have it reviewed and approved, and have a *different* stranger see it in Live Lots
and place a real, server-validated bid that persists and is reflected back correctly. That's
the mission's own bar, minus two things: (1) delivery — the one-time code only reaches a
server console today (gates #1/#2, unchanged), and (2) the storage — in-memory means every

Both were already known blockers; today's work makes what happens *before* those two things
demonstrably work, which wasn't true this morning because of the bug in part 1.
